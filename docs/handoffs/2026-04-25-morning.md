## Notes / observations / aside

This is the first handoff under CONTINUITY_PROTOCOL_V1. Compare its structure to prior handoffs (free-prose, 250+ lines of mixed durable and ephemeral content). This handoff is ~120 lines because most of what would have been included is now in CLAUDE.md, ADRs, or SYSTEM-STATE.md. That compression is the protocol working as designed.

Two patterns Claude noted from this session worth carrying forward:

1. **Read the actual log first.** When the same symptom recurs (stale dashboard / index.lock), the fix is in the log. Tonight `~/logs/git-push.log` contained the smoking gun — V1's misclassification — and the fix took ~30 minutes once we read it carefully. Yesterday morning's incident took hours partly because we recovered the symptom without reading the log carefully. Lesson reinforced: real diagnosis from logs first, fix second.

2. **Silent failure deserves immediate priority.** Build queue had "harden git-push-queue" deferred from yesterday. It hit again today. If a bug class is "fails silently in normal-looking output," that bug class should jump the queue, because while it exists you have no way to know the system is working. This was identified yesterday but not acted on; today it cost ~2.5 hours of stale dashboard. Worth a standing rule for the protocol: silent-failure bugs skip normal prioritization.

(Possible future ADR: "operating principle — silent-failure bug class skips queue.")
